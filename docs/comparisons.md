# Immutable document comparisons

These D102 comparison controls serve code revisions, papers and prose drafts. The comparison is a reading view over two immutable source snapshots. It does not change a document, record review evidence, accept a revision or invoke a model.

## Reading first

The comparison precedes revision management panels. Version selectors, view tabs, file selection and change navigation remain visible. **Comparison options**, closed initially, contains Words/Lines, Swap, Show Current, the target snapshot and the space/tab navigation preference. Opening or closing it changes no source or saved selection. Keyboard shortcuts ignore a focused disclosure summary, just as they ignore other controls.

Word uses the same reading order and a separate **Word comparison options** disclosure. Its version pair, scope and Words/Lines controls remain visible, along with a concise text-only limitation and whether the original Word packages differ. Full projection limits, package identities, scope navigation and reader/reset actions remain available inside the disclosure. Unavailable-source, access, offline and storage warnings remain visible. Word retains literal projected-text comparison; rendered document comparison remains open.

D102b verification passed type checking, both production builds and the full suite (1,894 total: 1,885 passed, nine optional TeX integrations skipped). The final builds passed 96 desktop/mobile browser checks across root and mounted paths, covering layout, exact pairs, drafts, narration, offline reopening, source revocation, password-session retirement and existing PDF source navigation. Four real-compiler browser cases were skipped because no isolated compiler was configured. Preview data and schema were preserved exactly. Browser mobile emulation does not qualify physical iOS/Android devices.

## Selecting what to inspect

The initial view compares the current version with its immediate predecessor, or an empty base for the first version. It resolves that choice once. Thereafter the selection records the revision ID, both exact version IDs and content hashes, the file path, literal comparison mode and source/comparison view. Background refreshes and newly arriving versions do not silently replace the selected pair. Show Current is an explicit return to the latest pair.

Either side can be any available version of the same revision. Equal and reverse comparisons are supported. Changing the inspected version preserves the chosen base; Swap reverses a nonempty pair. A missing version or mismatched content hash produces an unavailable-selection state rather than substituting another snapshot.

The file chooser uses the union of the two snapshots' exact paths: target paths in snapshot order, followed by base-only paths in their snapshot order. Previous File and Next File traverse that same list without wrapping, changing the pair, or skipping unchanged, empty or deleted files. Added, deleted and existing empty files remain distinct. Selecting a deleted file shows its removed content; it does not fall back to a different current file. File renames are currently an addition and deletion, without inferred alignment.

Selection metadata follows the existing workspace and account cache boundaries. Local mode can retain it with the visited revision for offline reopening. Password mode keeps it only in the verified session's memory. Object revocation clears the metadata along with cached source; logout/account changes cannot restore another account's selection. No extra source text or spoken excerpts are stored with the selection. If browser storage fails, the current view remains usable but cannot promise restoration after reload.

## Literal changes and navigation

Words and Lines are literal modes. Both preserve whitespace, CRLF, Unicode and final-newline differences. They do not interpret LaTeX, infer semantic equivalence, rewrite the source or call an AI provider. Only the selected file is compared.

Adjacent additions and removals form one changed passage. Previous Change and Next Change move the same cursor used by voice commands. The view reports its current passage and total, and navigation stops at the first or last passage instead of wrapping. An unchanged file and an empty file addition/deletion have explicit states.

The optional **Skip space/tab-only changes** preference affects passage navigation and narration. It is off by default, including for older saved selections. A complete changed passage is skipped only if removing ASCII spaces and tabs from both changed texts makes them identical. Added/deleted files are never skipped by this rule. Line endings, non-breaking spaces, other Unicode whitespace and mixed text edits remain eligible. All literal additions and deletions stay visible with their original offsets, and the view reports skipped and eligible counts. An entirely filtered comparison says that no passages remain under the filter; it never claims the files have no changes. This is a literal presentation preference, not a judgement that whitespace cannot affect meaning.

The `j` and `k` shortcuts move between eligible changes. `Shift+J` and `Shift+K` move between files. They stop at boundaries, share the button/voice cursors, and do not activate when focus is in an editor or form control, when text is selected, during IME input, with other modifier keys, or while a dialog is open. Same-target presentation navigation retains an open source editor and its draft; moving to another target snapshot closes that editor while preserving its saved draft.

The pure shared comparison helper bounds combined source size, source lines, token count, edit distance, token comparisons, rendered segments and changed passages. Its hard ceilings are 200,000 UTF-16 source units, 8,000 source lines, 40,000 tokens, edit distance 1,024, 250,000 token comparisons, 2,000 segments, 1,000 passages and 120,000 rendered UTF-16 units. Callers may lower these limits, but cannot raise them. These bound computational work; they are not a wall-clock guarantee for every device.

An exceeded limit produces an explicit unavailable comparison with the selected source/download alternatives. It never reports a truncated diff as “no changes.” Raw source remains the exact snapshot; a comparison fallback does not edit or shorten it.

Source comments and the paper structure view have a separate target-only display budget of 120,000 UTF-16 units and 8,000 displayed lines. A small target remains available for source comments even when a large base prevents comparison. An oversized target remains readable as raw source or downloadable, with an explicit notice that inline comments and structure are unavailable for that file.

## Aligning source paragraphs

For papers and prose documents, **Align source paragraphs** is an optional Words-mode setting under Comparison options. It is off by default and persists only as presentation metadata alongside the immutable pair. Code, Lines mode and Word projections retain their existing literal comparison. The setting changes neither source nor comments, suggestions, review evidence or acceptance.

Physical source paragraphs are blocks separated by blank lines containing only ASCII spaces or tabs. LF and CRLF are preserved, bare CR remains content, and non-breaking spaces do not create blank separators. A wrapped LaTeX block is a source paragraph, not a parsed or rendered paragraph. There is no TeX execution, semantic interpretation or model call.

Unique exact paragraph bodies establish an ordered backbone. Exact bodies outside that backbone receive **Reordered source paragraph** labels and buttons that focus their corresponding addition or removal. Both sides remain visible in full, with their original source offsets and existing passage indexes. The labels describe exact text matches, not proof of an author's editing history. Reversing a pair may select a different equally valid backbone. Repeated, copied or edited paragraphs are not guessed as matches, and shifting unchanged paragraphs by inserting text does not imply a reorder.

Ordinary gaps receive literal word comparisons. Gaps containing reordered paragraphs keep complete removals and additions, so nearby edits may appear coarser. Paragraph alignment shares the normal aggregate token, comparison, edit and rendering budgets, plus a combined ceiling of 2,000 paragraphs. Exceeding any budget returns no partial comparison. Source downloads remain available.

Counterpart buttons share the usual change cursor and narration. Deferred focus is retired when the selected pair/file, session, access or source generation changes. Speech identifies source paragraph alignment without calling it rendered or semantic comparison. Comments keep their original anchors; paragraph matches never relocate them. D106b separately adds discussion on the exact removed or added source described below.

## Reading the selected changes aloud

Typed and spoken commands share the active review selection:

- **Read changes** names the revision, base and inspected versions, and selected file, then reads up to three changed passages.
- **Read current change** reads the passage selected by the on-screen cursor.
- **Next change** and **Previous change** move that same cursor and describe the selected passage, with explicit end-of-list feedback.
- **Next file** and **Previous file** select the adjacent file in the exact pair and read its first eligible change, or its unchanged/empty/filtered/too-large state. They never advance to newer versions or wrap around the file list.

Narration distinguishes added/deleted files and names significant whitespace instead of treating it as empty text. When filtering is enabled, it names the filter and gives eligible/skipped counts using the same original passage indexes as the screen. Long filenames, source excerpts and total speech have explicit shortening notices. The response is bounded to 2,200 Unicode code points. No command independently compares the latest version or silently reads another file. Large-comparison failures are spoken as failures to compare, not empty-change summaries.

Changing the version pair, file or comparison mode, leaving the revision, losing access or ending the session cancels old comparison speech. A spoken file-navigation command preserves its new response only across that exact destination transition. Stopping listening or turning spoken responses off cancels narration; delayed speech and recognition callbacks cannot restore it or prevent listening from restarting. Playback uses only browser voices marked as local; it does not send document text to a remote speech voice. Microphone capture pauses during narration to prevent spoken output from executing commands, so interrupting playback currently requires a button or typed command. Browser speech recognition remains separately opt-in and may send microphone audio to its provider. Offline transcription and spoken interruption during playback remain unfinished.

## Comments, edits and evidence

D106b is implemented and verified. **Comment on removed text** chooses the exact base passage, and **Comment on added text** chooses the exact target passage. These buttons appear above the diff for the active change selected by Previous/Next change; they name the source version and leave the selected pair and file unchanged. A deleted file can receive a comment on its original base source. Reversing the comparison changes its displayed side without changing that source identity. Both line gutters also select an exact passage in their respective version, excluding the line's LF or CRLF terminator. Empty lines have no nonempty passage; use a neighboring passage or a range in Source. Passage validation retains the existing 20,000 UTF-16-unit limit and rejects invalid or split-surrogate boundaries rather than clipping the quotation.

One comment composer sits immediately below the comparison and stays available when switching the Discussion, Review evidence, History and References tabs. **Comment version** chooses either compared version or the retained comment destination when it is outside the reading pair. Each immutable version keeps its own draft and original anchor. Choosing another version restores its separate draft rather than moving the current text there. Selecting a different anchor within the same nonempty draft asks before replacing its location or discarding a proposed replacement. The destination choice is in-memory presentation state; after reload the composer initially uses the inspected target, and the version chooser can reopen a retained base draft. Local and authenticated draft storage retain their existing device/session boundaries.

While a comment or private draft is saving, its destination and text stay pinned and other comment-target actions are disabled. The reader can still change the comparison. Completion clears only the matching submitted draft; it cannot clear a newer draft or switch the reading pair. Selecting another comment version retires a private-publication preview. Private saves and complete-review publication retain their existing exact-request retry and explicit-publication rules.

Up to 20 qualifying threads appear as reading excerpts beside their original source. Placement requires the exact revision, version, hash, path, offsets, quotation and surrounding context. Cards appear after the final overlapping source segment or line. An equal-version pair shows each thread once on the target side; reversing the pair changes only its presentation side. Quotes, comment bodies and the last three replies are bounded excerpts, with full discussion available below. When more than 20 threads qualify, a visible count explains the limit. **Open discussion** selects the existing thread in the all-version discussion list without changing the comparison, duplicating an editor or changing its collapse preference.

Inline placement never searches for a quotation in a different version, uses a reordered-paragraph match as a new anchor, or fabricates a passage for a legacy line-only comment. Those discussions remain available in the full list, whose separately labeled quotation projection is unchanged. Word projected comparisons keep their separate original-package passage controls. D106b adds no Word diff-side anchors, arbitrary selection across mixed diff text, inline reply editors or per-inline keyboard navigation. D106c adds [multi-passage suggestions](suggested-edits.md) by selecting separate exact passages from one original text version; it does not infer a single selection across mixed base/target diff text or modify Word packages.

D106b verification passed type checking, root and mounted production builds, and the full suite (1,931 total: 1,922 passed, nine optional TeX integrations skipped). The verified builds passed 280 desktop/mobile browser checks covering exact side anchors, deleted files, reversed pairs, historical suggestions, separate offline drafts, delayed saves, private publication, read-only access, focus retirement and existing Word/reply/voice flows. Preview schema and all existing rows remained unchanged. Mobile checks use Chromium touch emulation, not physical devices.

Creating a new version and applying a suggestion remain explicit source-changing operations. Their successful result may select the new snapshot when the original editor still owns the current view, preserving the reading mode and file when it remains in the new pair. A delayed save cannot discard a newer draft or take over a comparison that the reader selected while that save was pending.

Review runs remain bound to a version ID and content hash. Inspecting a historical or reversed comparison does not make old evidence current or re-enable acceptance for a newer snapshot. Historical suggestions can retain a proposed replacement, but cannot apply it to a later source. Existing server checks continue to enforce revision-owned versions, exact passage anchors and current-version acceptance. D106b uses the existing comment and private-review APIs without a schema change; it does not by itself change source, review evidence or acceptance.

## Review finding navigation

O203a adds a separate cursor in **Review evidence** for text revisions, papers and prose. The selected recorded run pins its review ID, revision ID, immutable source version and content hash; the finding ID is scoped to that run. Different runs may reuse finding IDs. The run selector exposes historical results and names the provider, model, source version and recording time. An absent preference can initially choose the latest recorded run for the inspected version. Once chosen, new runs and source versions do not replace it. Invalid or retired preferences show an unavailable state until the reader explicitly chooses another run.

On-device deterministic checks have a unique transient analysis identity and the same exact source pins. They remain labeled as unrecorded and cannot satisfy acceptance. Their analysis survives only in the current tab. A new result exposes **View new on-device checks** while preserving the reader's saved selection. A saved source-free selection marker makes a retired result explicitly unavailable after reload; it never silently revives an older recorded run. Local deterministic checks, local AI and hosted AI retain distinct provenance in the screen and narration. Reading findings does not run checks, request a model, create a comment or change acceptance.

Previous/Next finding, `n/p`, and the corresponding voice commands share the stored result order and stop at its boundaries. Cards are paged in groups of 25 without dropping findings from navigation or counts. Keyboard shortcuts do not activate in editors, controls or dialogs, during IME input, or while text is selected. **Read findings** names the source and provenance, then reads up to three findings; **Read current finding** reads the selected finding. Narration is bounded to 2,200 Unicode code points with explicit shortening notices. Local browser speech, cancellation and microphone behavior follow the comparison contracts above.

**Open original finding source** validates the run's exact version and hash, an unambiguous file path, and a valid one-based line in that original file. It selects and focuses that source without creating a comment target. There is no line-one fallback, quotation search or relocation onto newer text. A missing, invalid, ambiguous or oversized source location leaves the finding readable and disables the source jump. Word package automated reviews and Word finding anchors remain unsupported.

The navigator accepts at most 20,000 findings, 100,000 UTF-16 units per text field and 2,000,000 aggregate text units per complete analysis. Each complete revision version/review inventory is bounded at 10,000 items. An oversized or malformed analysis or inventory is explicitly unavailable; it is never shown as an empty or partial review. Source jumps additionally require at most 1,000 files in the source inventory and a file within the inline limits of 120,000 UTF-16 units and 8,000 LF-counted lines. These are display bounds, not a review-quality guarantee.

Only selection identities are stored alongside the existing authorized revision cache. Source text, findings and narration are not duplicated in selection metadata. Local offline reopening, password-session memory and source/File/repository access ceilings remain distinct. Access or account changes retire old controllers and narration. Changing the selected run, source context or evidence payload likewise invalidates pending speech and focus callbacks.

The pinned [Differential Harbormaster field](https://github.com/phacility/phabricator/blob/5720a38cfe95b00ca4be5016dd0d2f3195f4fa04/src/applications/differential/customfield/DifferentialHarbormasterField.php) loads messages for the selected diff's build targets, with a legacy-property fallback. Our native finding navigator instead preserves recorded order and requires a valid original line. O203a does not implement Harbormaster plans, build-target ingestion, upstream lint/unit protocols, byte-column ranges or automatic inline lint publication. Finding disputes, waivers, grounded claims/citations, automated suggested edits and evaluation fixtures remain separate work.

D102 remains partial. Semantic move detection, structural/formatting-aware filters, rename alignment, rendered PDF comparison, inline-thread keyboard navigation and upstream interdiff/import compatibility remain open. Arbitrary selection across mixed diff text and Word package proposals remain separate work. Version-pinned PDF viewing and SyncTeX source navigation are available through [paper builds](paper-builds.md); they do not yet compare rendered versions. The literal comparison does not claim to distinguish rewritten meaning, validate scientific or legal claims, or complete Differential parity.
