# Audio inbox

O202a provides an explicit audio inbox at `#audio` for recording thoughts, paper notes and drafting instructions. It keeps the original browser-produced audio bytes. Recording itself does not transcribe, interpret, upload, create a task, or modify a document. O202b adds a separate explicit on-device transcription workflow. Confirmed dictation into source remains separate work.

## Capture and microphone ownership

Choose **Record audio** to request microphone permission and begin capture with `getUserMedia` and `MediaRecorder`. The application never requests the microphone merely because this page opens. A pending request can be canceled; an eventual permission grant after cancellation, navigation or session retirement has all tracks stopped and cannot start a recorder.

Audio capture owns a microphone lease in the current tab before requesting permission. It synchronously stops this tab's voice command recognition, closes the command panel and prevents another command recognizer or audio recorder in the tab from acquiring the microphone while permission or capture is active. Finishing, canceling and all failure paths release the lease. The lease does not control other tabs or applications. Command recognition has its own consent and browser-provider limitations; recording audio does not grant consent to it.

The static application permits same-origin and Blob media in its content security policy so local playback works. Local transcription permits WASM compilation and same-origin workers; it does not permit general JavaScript evaluation or Blob scripts. The service worker verifies installed runtime bytes before serving them, and gives the transcription worker a policy that prohibits network connections.

**Stop recording** stops the microphone tracks and waits for the recorder's final audio event. Unsupported media APIs, denied permission, unavailable input, recorder failures, empty output and failure to finalize are explicit errors. No unsuccessful or partial container is presented as a completed recording. A track ending naturally produces a notice to check playback before saving. Native playback failure leaves the original bytes available to download.

The complete clip is bounded to 25 MiB and ten minutes of observed capture time. Each delivered chunk, including the final one, is checked before retention. A chunk that would exceed the byte bound rejects the complete capture without clipping arbitrary bytes. The stop timer is scheduled at 9 minutes 59 seconds to allow ordinary scheduling jitter; actual elapsed time at track stop is recorded. A delayed stop beyond ten minutes is rejected rather than silently changing duration metadata. Duration is observed wall time, not a claim to have decoded and verified every encoded sample.

The recorder requests chunks about once per second, but chunk delivery is not a reliable clock. Browser suspension, phone locks and media implementations may delay events or provide a large final chunk. The app stops capture when the page becomes hidden and makes no background-recording guarantee. The [MediaRecorder event documentation](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event) describes these timing limitations. Actual microphone/device and mobile browser behavior still require physical-device verification.

## Explicit retention and export

A successful stop creates one **Temporary recording** with a title, approximate duration, size and playback controls. Choose **Save on this device** in local mode or **Keep for this session** in a password workspace to retain it. Download and discard are separate explicit actions. Download exports the original Blob without conversion or transcription; the filename uses a safe title and the recorded MIME type.

The finished temporary clip stays in the active session's memory when navigating elsewhere in the app. Reopening Audio restores it. It is cleared on page exit, reload or session lock, and a browser unload guard warns while it exists. Leaving the audio page during an unfinished capture cancels and discards that capture; the page explains this before recording. Stop first to preserve a finished clip. A fresh recording cannot overwrite the current temporary clip.

Local-mode saves use IndexedDB, logically namespaced by application mount and workspace. A saved clip contains an opaque ID, title, creation time, MIME type, observed duration, byte count and Blob. There is no audio server API or mutation outbox entry. A successful save is reported only after the storage transaction commits and the original session is still active. Browser quota failure or unavailable storage leaves the temporary Blob available for playback, download and explicit retry. Local browser data may be evicted or cleared; saving locally is not a backup.

Password-mode retention uses the current verified tab session's memory. It never opens IndexedDB or falls back to browser persistence. It survives ordinary in-app navigation but is cleared when the session locks, the page reloads or closes, the account changes, or the user signs out. Download recordings separately before those events; the general draft JSON export does not contain audio. Session expiry is checked at action boundaries as well as by the session timer. Neither local mount namespacing nor account memory is isolation from scripts already executing in the same origin.

The inbox permits at most 100 saved recordings and 200 MiB in total, in either retention mode. Each clip requires consistent MIME/Blob size metadata, a valid identity and creation time, a nonempty title of at most 200 UTF-16 code units, and the capture limits above. Saving serializes these inventory checks with the write. Malformed or unsupported stored records are reported and retained unchanged. Known valid recordings remain readable, but new saves are blocked when the inventory cannot be accounted for safely. The inbox does not silently repair, overwrite or delete unrecognized data.

Saved recordings support playback, original-byte download and a title-specific delete confirmation. Deleting a clip removes that chosen retained record and its saved transcripts. Object URLs are temporary and revoked when their view retires; page exit and session lock also pause playback and clear temporary UI references. A local page restored from the browser's page cache refreshes the saved inbox and cannot revive a discarded temporary recording.

## Local transcription

The **Local transcription model** panel below recording controls offers an explicit **Install model** action. It downloads the public English Whisper tiny.en q8 model and this build’s browser runtime from the operator’s same-origin staging paths. The model is `onnx-community/whisper-tiny.en` at revision `2575352d61be1bf7225cf8f8b268a4678025fc58`, using Transformers.js 4.3.1. Every model file is pinned by byte count and SHA-256; the runtime manifest identifies this build’s worker, JavaScript factory and WASM binary. Opening Audio, checking installation status and transcribing do not download missing model files. A missing, corrupt or different-build installation requires explicit installation again. Canceling a download leaves no completed installation marker. Public model weights may remain cached across accounts; audio and transcript data never enter that cache.

Installation requires a controlling service worker, Cache Storage and Web Locks. The public cache is scoped to the application origin and mount. Installation and removal hold an exclusive lock, while verified reads hold shared locks; the completed marker is written only after every asset passes verification. The service worker independently verifies runtime files and returns an explicit failure for missing or corrupt bytes without fetching substitutes. Cross-tab invalidation uses BroadcastChannel with a public storage-nonce fallback. If neither notification transport is available, model installation or removal fails explicitly. These boundaries prevent partial installations and mixed builds; they do not protect against scripts already executing in the same origin.

An installed and verified model runs on the browser’s CPU with single-thread WASM. Choose a clip’s **Transcription** disclosure, then **Transcribe on this device**. The application reads the original encoded Blob, verifies the complete cached installation, hashes and decodes the audio locally, and runs a dedicated worker. Progress reports actual stages—hashing, decoding, model loading and transcription—rather than an invented completion percentage. English is the only supported language in this slice. Audio must decode successfully within the ten-minute, 25 MiB limits; unsupported codecs, oversized decoded audio and runtime failures are explicit. Output is bounded to 100,000 UTF-16 code units, and a run times out after 30 minutes. Keep the page open: mobile suspension and background compute are not guaranteed.

Decoding uses 16 kHz audio and averages mono or stereo channels without trimming. The browser allocates decoded audio internally before the application can check its duration and channel count; these are accepted-input/output limits, not a hard native-memory cap. Physical-device resource limits still need qualification.

**Cancel transcription**, leaving its open view, audio deletion, model removal or replacement, page exit, session expiry and lock retire the work. The worker is terminated, decoded data and pending callbacks are discarded, and a late completion cannot populate another clip or account. Only one clip can be transcribed at a time in the inbox. Removing a model cancels inference using it and keeps audio and saved transcripts. Cross-tab model invalidation communicates only the public mount identity, never private input or output.

The **Original model transcript** is immutable, unverified AI output. It can omit or invent words; listen to the recording before relying on it. The exact original encoded-audio SHA-256, byte count, MIME type, model repository/revision/manifest SHA-256, runtime version, decoding options and run identity are visible in the provenance disclosure. An empty model output is displayed as empty. The separate **Transcript draft** starts from the result, can be edited, and has its own save. Selecting a historical run never overwrites the draft; **Replace draft with this result** is explicit. Original and draft text have separate copy and plain-text download controls. Neither operation edits a revision, paper, task, discussion or voice command.

**Save transcript** retains up to five immutable results and one editable draft in the saved audio’s existing IndexedDB row in local mode, or in tab-session memory in password mode. Audio must be explicitly saved or kept first; temporary recordings can still be transcribed and their text exported. Every save verifies the actual Blob’s SHA-256 and metadata, then uses a transcript revision check inside the atomic row update. Conflicting saves from another view fail visibly; reload the saved transcript before retrying, while the unsaved result and draft remain exportable. A quota failure does not claim success or consume the current text. Transcript persistence never replaces the original audio. There is no schema migration or server transcript endpoint.

If another tab clears the saved result underlying an edited draft, reloading saved transcripts does not hide or discard that draft. Its text remains editable, copyable and downloadable, including offline and after ordinary in-app navigation. The view explicitly identifies the unavailable original result and disables saving until the draft refers to an available result. Generating another result does not silently rebind the old draft; replacing it is an explicit action. The normal unsaved-text session lifetime still applies.

At five results, another save fails without silently evicting evidence. **Clear saved transcripts** asks for confirmation and clears retained results and the saved draft while keeping audio and any newly generated unsaved result. Deleting audio deletes its transcripts atomically. Malformed, unsupported or mismatched transcript data remains unchanged and does not prevent downloading valid original audio. The limited format currently recognizes the pinned English model and runtime; future model formats require a deliberate compatibility change.

Unsaved transcript results and edits survive ordinary hash navigation in the active session. They are cleared when leaving the browser page, reloading, signing out or locking, with an unload guard while unsaved text exists. Page-cache restoration reloads saved local transcripts; it cannot revive retired unsaved text. In password mode, page exit—including entry into the browser page cache—locks the session and clears saved audio and transcripts as well as unsaved text; returning requires verification and cannot restore that private memory. Password transcripts have the same memory-only lifetime as their audio and are excluded from the general draft JSON export. Export text separately before the session ends. Object URLs and clipboard completion feedback are retired with their originating clip/view/session.

## Operator setup

The server never downloads model files on startup or in response to a transcription request. Stage the pinned public assets explicitly into a **fresh** directory, then configure the reusable server path:

```sh
npm run transcription:model -- --directory .data/speech-model
npm run build
APP_TRANSCRIPTION_MODEL_DIR=.data/speech-model npm start
```

The staging command fetches the exact model revision, checks every file’s declared size and SHA-256, and atomically promotes a completed directory. It refuses to overwrite an existing destination; choose a new directory for a deliberate update. A failed or interrupted staging run removes its incomplete directory. Keep operator infrastructure and domain configuration outside this repository. Normal authentication and mount settings still apply.

The pinned public model is approximately 43.5 MB, plus approximately 14.8 MB of browser runtime in the current production build. Exact bytes and hashes are recorded in the manifests; browser storage overhead is additional. The MIT model license and model card are included with the staged files, with dependency attribution in `NOTICE`. `npm run build` emits the worker/runtime assets and the exact runtime manifest into the application distribution. No model weight is bundled into the application source or normal app-shell cache.

`APP_TRANSCRIPTION_MODEL_DIR` enables read-only serving of verified public model assets at the application mount. Without it, installation reports an unavailable or incomplete operator-staged model. **Install model** is still a separate user action, even when the operator has staged files. Public model resources are cacheable across accounts and intentionally contain no workspace data, audio or transcript text. Audio and transcript lifetime continues to follow local versus password mode. Clearing the public model cache cannot recover or delete private audio.

## Scope and verification

This is a native extension beyond the pinned Phabricator feature set. The recognizably separate application, explicit actions and shared session boundaries follow the existing workspace interface. Core storage and microphone tests cover retention limits, malformed records, quota/atomic write behavior and session retirement. Browser tests use real `MediaRecorder` output from synthetic audio for the capture/export path, with controlled permission/error events for failure boundaries; they do not establish physical microphone quality or universal codec support.

Verified for O202a: `npm run check`, `npm test` (1,653 total: 1,644 passed, nine optional TeX checks skipped), and production builds at `/` and `/workspace/`. The browser matrix passed 76 unique cases: eight audio workflows and eleven existing authentication, mount and discussion/voice cases in both desktop/mobile viewports at both mounts. It covers native synthetic-audio encoding and decoding, exact downloads, saved audio after offline reload and page-cache restoration, session retirement, late permissions, storage failures and microphone ownership. A pre-fix control failed the detached audio-source cleanup assertion; the final implementation passes it. Physical-device microphone/codec behavior remains unverified.

The local preview was installed and restarted for O202a and O202b. Exact schema, rows, row IDs, foreign keys and integrity checks matched the preserved baseline, as did health/document responses. The final served application assets matched the candidate build and the public model manifest passed its pinned SHA-256 check. The schema remains 34; O202b adds no server schema migration.

Verified for O202b: `npm run check`, `npm test` (1,685 total: 1,676 passed, nine optional TeX checks skipped, zero failures), and production builds at `/` and `/workspace/`. Tests cover pinned staging, existing-directory refusal, interrupted downloads, atomic cache installation/removal, corrupt and missing assets, runtime requests without network fallback, mount isolation, decoder bounds, cancellation, source-bound transcript storage and session retirement. Actual staging of the public model passed its byte and digest checks.

The final browser matrix passed 92 unique cases across desktop/mobile Chromium viewports at both mounts: 16 real-transcription cases, 32 existing audio cases and 44 authentication, mount and discussion/voice regressions. Actual Whisper CPU inference on the committed spoken-audio fixture verifies cold offline reload, immutable original output and editable saved drafts, missing weights, real-worker cancellation, orphaned draft recovery and password-session retirement. Tests monitor network requests and public caches for private audio/text leakage. A pre-fix control failed because clearing a saved result hid its edited draft; the final recovery case passed in all four viewport/mount combinations. Desktop and mobile screenshots were reviewed. These real inference checks are not a transcription-accuracy benchmark.

A fresh production-only installation outside the repository passed with `npm ci --omit=dev`. The server started against a disposable database, returned healthy application responses, served WASM with the correct MIME type, and returned the expected unavailable-model response without staged weights. Transformers.js and both browser/native ONNX runtime packages were absent from that install; browser inference uses the already-built distribution. The smoke check ran on macOS ARM64 with Node 22.14 and does not establish a Linux deployment result.

The dedicated public CI job stages the pinned model and runs the real-transcription tests at both mounts on desktop/mobile Chromium. Its configuration is present; a successful hosted CI run is a separate result. Physical iOS/Android devices, long-recording performance, native decoder peak memory and broader speech/codec accuracy remain unqualified.

Not implemented: automatic or provider transcription, languages other than English, word timestamps, speaker labels, speech-to-source editing, uploaded audio import, waveform or trimming tools, resumable background capture, cross-device audio synchronization, durable authenticated audio retention, encrypted audio vaults, server uploads, provider integration and automatic retention policies. Raw audio stays private to the current browser retention mode until the user explicitly downloads it.
